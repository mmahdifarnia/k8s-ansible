# Kubernetes Cluster Deployment with Ansible and Vagrant

This project provides an automated way to deploy a Kubernetes cluster using Ansible for provisioning and Vagrant for virtual machine management.

## Prerequisites

Before you begin, ensure you have the following installed:

*   **Vagrant**: [https://www.vagrantup.com/downloads.html](https://www.vagrantup.com/downloads.html)
*   **VirtualBox**: [https://www.virtualbox.org/wiki/Downloads](https://www.virtualbox.org/wiki/Downloads) (or another Vagrant-supported provider)
*   **Ansible**: `pip install ansible`

## Project Structure

*   `Vagrantfile`: Defines the virtual machines (master and worker nodes) and their network configuration.
*   `ansible.cfg`: Ansible configuration file.
*   `playbooks/`: Contains Ansible playbooks for different stages of the cluster deployment.
    *   `cluster.playbook.yml`: Main playbook to orchestrate the entire cluster setup.
    *   `config.playbook.yml`: Playbook for configuring Kubernetes components.
    *   `cri.playbook.yml`: Playbook for Container Runtime Interface (CRI) installation.
*   `roles/`: Contains Ansible roles.
    *   `k8s/`: Kubernetes deployment role.
        *   `tasks/`: Individual tasks for Kubernetes installation, cluster setup (master/worker), CNI, CRI, and configuration.
        *   `defaults/`, `handlers/`, `meta/`, `vars/`: Standard Ansible role directories.
*   `shell/`: Contains shell scripts used by Ansible playbooks.

## Setup and Usage

1.  **Clone the repository:**

    ```bash
    git clone <repository_url>
    cd <repository_directory>
    ```

2.  **Start the virtual machines:**

    This command will bring up the master and worker nodes defined in the `Vagrantfile`.

    ```bash
    vagrant up
    ```

3.  **Provision the Kubernetes cluster:**

    Once the virtual machines are running, use Ansible to provision the Kubernetes cluster. This will execute the main playbook (`cluster.playbook.yml`).

    ```bash
    ansible-playbook -i inventory playbooks/cluster.playbook.yml
    ```

    *Note: The `inventory` file is typically generated by Vagrant or needs to be created manually based on your `Vagrantfile` configuration. For this project, you might need to create a simple `inventory` file or modify the `ansible.cfg` to use Vagrant's inventory plugin.*

4.  **Access the Kubernetes cluster:**

    After successful provisioning, you can SSH into your master node and use `kubectl`.

    ```bash
    vagrant ssh master
    ```

    From within the master node, you can check the cluster status:

    ```bash
    kubectl get nodes
    kubectl get pods --all-namespaces
    ```

## Customization

*   **Vagrantfile**: Modify the `Vagrantfile` to change the number of worker nodes, VM resources (CPU, RAM), or network settings.
*   **Ansible Variables**: Adjust variables in `roles/k8s/defaults/main.yml` or `roles/k8s/vars/main.yml` to customize Kubernetes versions, CNI plugins, or other configurations.
*   **Ansible Playbooks/Roles**: Extend or modify the existing playbooks and roles to add more components or tailor the deployment to your specific needs.

## Troubleshooting

*   If `vagrant up` fails, check VirtualBox logs or Vagrant output for specific errors.
*   If Ansible provisioning fails, examine the Ansible output for error messages. Ensure all prerequisites are met and SSH connectivity to VMs is working.
*   For Kubernetes-specific issues, check logs on the master and worker nodes (`journalctl -u kubelet`, `crictl logs`, etc.).
